## Architectural Decisions & Deviations (History)
- `Task 3.7`: Implemented V07 Weak Session & Authentication Controls in `backend/app/routes/auth.py` and `frontend/src/services/api.js`. `create_access_token` issues non-expiring JWTs (omitting the `exp` claim) signed with a static hardcoded key (`medivault-insecure-hardcoded-secret-key-12345`), trivial passwords (e.g. `123`) are accepted on registration and login without complexity checks, and tokens are stored in `localStorage` via `tokenService`. Documented in `docs/vulnerability_refs.json` (lines 45–56 in `auth.py`, lines 9–15 in `api.js`). Verified via `scripts/verify_v07.py` confirming registration and login with password `123`, lack of `exp` in decoded claims, and `localStorage` persistence, test suite passing (27/27), and clean Vite build (`npm run build`).
- `Task 3.6`: Implemented V06 Insecure File Upload Validation in `backend/app/routes/reports.py`. Multipart document upload (`POST /api/reports/upload`) trusts the client `file.filename` and `file.content_type`, applies no file extension allow-list, magic byte checks, or file size limits, and stores files under their original raw filenames in `lab-data/uploads/`. Combined with V05, uploaded `.html` and `.svg` files can be directly browsed at `/public/uploads/` leading to stored XSS. Documented in `docs/vulnerability_refs.json` (lines 85–95). Verified in `scripts/verify_v06.py` with HTML and SVG uploads returning 201 Created and serving unauthenticated scripts, test suite passing (27/27), and clean Vite build (`npm run build`).

Documented in `docs/vulnerability_refs.json` (lines 37–40). Verified via `scripts/verify_v05.py` with unauthenticated GET requests returning 200 OK for `backup_dump.sql` (exposing SQL schema, accounts, and PII) and clinical PDF reports/prescriptions, test suite passing (27/27), and clean Vite build (`npm run build`).
